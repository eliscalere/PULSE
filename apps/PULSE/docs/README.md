# PULSE Documentation

## Where to look

| Folder / file | What it is | Audience |
|---|---|---|
| **`current/`** | Canonical current documentation release — User Guide, Technical Handoff, Operations SOP. Each provided as `.md` (web/search-friendly) and `_Final.docx` (print/submit). Start here. | All |
| `architecture/` | Deep technical references: SP list schema guide, Forge deployment guide, Firepit app architecture. | Developers |
| `handoff/` | Forge deployment steps, FS-specific notes. | Sysadmin / developer |
| `requirements/` | Original requirements and implementation notes. | PM / developer |

| `screenshots/` | Annotated screenshots referenced in docs. | All |
| `OVERVIEW-PPTX-DATA-SCHEMA.md` | Schema for the Overview PPTX export feature. | Developer |
| `PRODUCT.md` | Product context used by impeccable skill. | Developer tooling |
| `PULSE-IPT-SOP.pdf` | Original SOP PDF. | Operator |
| `legacy/` | Earlier numbered doc drafts (`01-USER-GUIDE`, `02-TECHNICAL-REFERENCE`, `03-OVERVIEW`). Superseded by `current/`. Keep for reference only. | — |

## Which docx is authoritative?

In `current/`, files ending in `_Final.docx` are the finalized, submit-ready versions. The matching `.docx` (without `_Final`) are intermediate drafts. The `.md` files are the live-editable source; Word docs embed screenshots for offline use.
