 01 / START A SESSION



 Confirm identity, review attention items, and
 enter through the correct module
 Access: Open PULSE from the approved SharePoint page. PULSE uses the active SharePoint session and does not present a
 separate PULSE password screen.

 Before acting: Confirm the name and role shown in the upper-right account area. Review Dashboard, My Work, meeting actions,
 and notification items before opening a record.


      LOCAL FALLBACK The local browser fallback is intended for interface development only. It is not an official record and does not
      confirm SharePoint identity, permissions, or persistence.




                                          Dashboard - quick access, personal work, meeting actions, and navigation



 Dashboard controls
  ●
      PULSE mark: returns to Dashboard from another module.
  ●
      Primary navigation: opens Overview, Projects, Weekly Meeting, Travel, Document Review, and available administrative routes.
  ●
      Quick-access cards: open a module or a focused secondary action.
  ●
      My Work: shows work associated with the current user and available source records.
  ●
      Report issue: starts a support ticket when the route is available.
  ●
      Bell and account control: open notifications and Notification Settings.

 04.1 / TRACKER, GANTT, AND BOARDS



 Maintain work with explicit owners, dates,
 condition, notes, and completion rules
 Tracker
 Use Tracker to create and maintain dividers, tasks, subtasks, owners, start dates, due dates, health, notes, and linked documents.

   Task field                        Current guidance


   Workflow status                   Not Started; In Progress; On Hold; Blocked; Complete


   Timing                            A past due date is a calculated timing condition, not another task status.


   Blocked or on hold                Explain the dependency, reason, and next action before relying on the state.


   Subtasks                          Maintain their own assignee, dates, and related records when needed.



 Gantt
 Use the Gantt view to inspect or maintain schedule placement and dependencies. A bar reflects tracker dates. Confirm the
 underlying start and due dates whenever timing changes.


 Boards
 Boards can use table or Kanban presentation. A new board begins with To Do, In Progress, and Complete columns; authorized
 owners may configure its columns and fields. Board completion is defined by the final configured column.


     CAUTION Do not move a visual bar or card without verifying the underlying work record and its dates, owner, and completion rule.

 04.2 / REPORTING, MEETINGS, NOTES, TICKETS, AND SETTINGS



 Convert project records into coordinated
 action without losing the source context
 Reporting
 Prepare milestones, technical bullets, risks, timelines, photos, and PowerPoint output. Check all source records before
 generating. A browser-generated file can download locally; when SharePoint mode is available, PULSE attempts project-file
 upload.


     DRAFT OUTPUT Treat every generated presentation as a draft until its content, filename, and destination have been verified.



 Meeting and Notes
 Use Meeting for project-scoped facilitation and Notes for contextual project notes. Record a decision separately from general
 notes. Create a tracked action whenever a follow-up has an owner or timing expectation.


 Tickets
 Use project Tickets to create or review project-linked support items. Include the route, record identifier, expected result, actual
 result, and an approved screenshot when reporting an issue.


 Settings
 Maintain authorized project metadata, lifecycle, technical health, dates, reporting configuration, and related fields. A change
 becomes an official record only when SharePoint persistence succeeds.

 05 / WEEKLY MEETING



 Run the shared cadence and turn discussion
 into named records and actions
 Reach it: Select Weekly Meeting. Use the available views to maintain the roster, agenda, Rocks, attendance, notes, decisions,
 project updates, action items, carry-forward work, and meeting history.




                                                 Weekly Meeting - shared cadence and meeting entry state



 Operating sequence
  ●
      Start or join the correct shared or project-specific session.
  ●
      Confirm the roster, attendance, guests, and agenda before working through updates.
  ●
      Capture decisions as they occur and keep explanatory notes concise.
  ●
      Convert each actionable follow-up into a named tracker item with an owner and timing expectation.
  ●
      Review carry-forward work and meeting history before ending the session.


      MEETING DISCIPLINE A note records context. A tracker item records accountable follow-up. Use both when an action results from
      the discussion.

 Submit, monitor, approve, finance, and close

   Request status                   Pending; Pending Finance; Approved; Denied; Revoked; Cancelled

 07 / DOCUMENT REVIEW



 Maintain formal review, revision, concurrence,
 final-pack, and signing history
 Reach it: Select Document Review. Create a review with its related project, document type, title, due date, revision label, current
 file, and reviewers or reviewer groups. Add signers only where sequential signing is required.




                                              Document Review - formal review and approval workflow

   Review value                   Meaning in the current workflow


   Not Started                    The review record exists but review activity has not begun.


   In Review                      Assigned reviewers are evaluating the current revision.


   Changes Requested              The current revision requires changes before review can continue.


   Review Complete                The review stage is complete.

 07.1 / REVIEW PROGRESSION



 Complete revisions without losing the review
 and signature history
      Review value                    Meaning in the current workflow


      Awaiting Final Pack             A final package must be prepared or uploaded.


      Signing in Progress             Sequential or required signature activity is underway.


      Signed                          The configured signing process is complete.


      Archived                        The record is retained outside the active workflow.




 Working sequence
  ●
       Confirm that the project, title, document type, due date, and current revision are correct.
  ●
       Assign the required reviewers or approved reviewer group.
  ●
       Record each decision against the current revision.
  ●
       When changes are requested, upload a new revision and repeat the required review.
  ●
       Prepare the final package before starting any configured signing sequence.
  ●
       Verify the signed or archived record and its retained revision history.


        REVISION CONTROL When changes are requested, upload a new revision and repeat the required review. Do not overwrite the
        reviewed revision.


        DISTINCT WORKFLOWS A file is not formally reviewed merely because it is stored in the project Documents area.

 08 / SUPPORT AND NOTIFICATIONS



 Create durable support records and configure
 how attention items reach you
 Support Tickets
 Reach it: Use Report issue, project Tickets, or an available ticket route. Record a clear title, description, affected project, priority,
 reporter, and status.

   Ticket value                    Use


   Open                            The issue has been recorded and still requires action.


   In Progress                     An assigned person is actively working the issue.


   Resolved                        The recorded issue has been addressed and the result can be verified.



 Notifications
 Use the bell to review items requiring attention. Notification Settings controls subscribed areas, delivery channels, and message
 tone where enabled. Adjust preferences for your own account only.




                                              Notification Settings - personal delivery, area, and tone controls

     VERIFY THE RECORD A notification is a routing aid. Always open the related record to confirm its current state and required action.

 09 / ADMINISTRATION



 Maintain the approved schema, users, roles,
 configuration, and traceability controls
 Reach it: Select Admin. Administrative routes and actions are intended for PULSE administrators and may not appear for other
 users.




                                               Admin - access-aware entry state and maintenance routes

   Administrative area                Operational guidance


   Diagnostics                        Use current diagnostics to identify environment, schema, or routing problems before changing configuration.


   SharePoint Setup                   Validate or provision the defined schema. Do not create ad hoc lists or columns.


   Users and roles                    Associate approved people, assign the least-privileged appropriate role, and preserve audit context when access
                                      changes.


   Locations and configuration        Maintain approved reference values and related system settings.


   Activity Log                       Inspect recorded actions for operational tracing and investigations.



     LEAST PRIVILEGE Project membership does not by itself grant PULSE administrative privileges. Assign only the access required for
     the user's current responsibilities.
